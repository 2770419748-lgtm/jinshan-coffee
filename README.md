# 进山咖啡小程序

进山咖啡的微信小程序和管理后台：

- **顾客**：首页顶上轮播新品和新书，下面三个入口：吧台自取、桌面扫码、预约（选营业时间里的取餐时间，先在线付款）；首页能进领券中心领代金券。在书架上选书、选计费方式下单，付款后到吧台取书；包天借书送的咖啡变成赠饮券。赠饮券和代金券点单时自动抵扣。下单时允许通知的，做好后微信里会收到取餐通知；按小时借书的，到期前 10 分钟收到提醒。
- **会员储值**：顾客充值（比如充 300 送 100、充 500 送 200，再送一年会员），余额能点单、借书、付超时费、付预约；会员期内借指定分类的书（默认漫画）免费、不计时。档位、赠送、会员天数、免费分类都在后台配。没开微信支付时顾客到吧台付钱，店员按会员号代充。储值不退，特殊情况店主线下退钱后在后台扣余额，每一笔变动都有记录。
- **店里**：小程序里有管理后台（接单、借书处理、改菜单、录书、计费规则、员工），按微信身份识别店主和员工，不用账号密码；电脑上还有网页后台，用微信扫码登录，多了每日汇总和 Excel 批量导入书目。收银电脑开着网页后台的订单页，来新单响铃并自动打小票。
- **付款**：没开通微信支付时顾客到吧台付，店员点「已收款」；开通后在服务器配置文件里填好商户号和证书，再到「店铺设置」打开开关，顾客就能在小程序里直接付，取消已付款的单会原路退款。

后端是自己的服务器（腾讯云轻量应用服务器 + 宝塔面板）：一个 Node.js 程序，不用装任何依赖，也不用装数据库，数据存在服务器上的一个 SQLite 文件里，每天自动备份。小程序和电脑网页后台都调这个服务器，网页后台也由它直接提供。

同一台服务器还跑着朋友的洗车店 **黑镜车体护理车房** 的小程序（`miniprogram-carwash/`，另一个 AppID、另一个商户号）：预约到店或上门洗车、洗车储值和次卡、技师接单。两个小程序认同一个人（会员号、券、员工身份通用），网页后台左上角切换「咖啡 / 洗车」。见「九、洗车小程序」。

咖啡和书籍分开管理：咖啡模块只读写 `coffee_` 开头的集合，书籍模块只读写 `book_` 开头的集合，员工角色也分开（咖啡师只进咖啡后台，书籍管理员只进书籍后台）。

## 一、准备：域名和备案

小程序只能访问备案过的 HTTPS 域名，所以要买一个域名，用这台服务器备案。备案要一到三周，越早开始越好；备案期间可以先按「四、备案下来之前先测试」用服务器 IP 试用。

1. **买域名**：腾讯云「域名注册」，`.com`、`.cn` 都行。买之前先建「域名信息模板」做实名认证，建议用个体户营业执照，和小程序是同一个主体，后面最省事。实名审核通过后才能备案。
2. **ICP 备案**：腾讯云「ICP 备案」→ 开始备案，备案资源选这台轻量应用服务器（包年的就可以）。按页面填主体信息（营业执照、经营者身份证）和网站信息，做人脸核验。之后腾讯云初审，再按工信部短信在 24 小时内完成核验，最后等管局审核。以腾讯云备案页面的要求为准。
   - 备案下来之前，域名先不要解析到服务器。
3. **小程序备案**：在微信公众平台首页按提示做「小程序备案」，可以和上面的域名备案同时进行。小程序备案通过后才能提审发布。
4. **备案通过后加解析**：腾讯云「云解析 DNS」→ 你的域名 → 添加记录：主机记录 `@`（或者 `api`，网址就是 `api.你的域名`），记录类型 `A`，记录值填服务器的公网 IP。

## 二、初始化宝塔面板

1. **拿到面板地址和密码**：腾讯云「轻量应用服务器」控制台 → 点进这台服务器 →「应用管理」，能看到宝塔面板的地址。按页面提示点「登录」打开终端，执行 `sudo /etc/init.d/bt default`，会显示面板地址、用户名和密码。
2. **第一次登录**：打开面板地址，用上面的用户名密码登录。要求绑定宝塔账号时，用手机号注册一个绑定。弹出「推荐安装套件」时直接关掉，不装 MySQL、PHP，2G 内存省着用。
3. **装 Nginx**：「软件商店」搜 Nginx → 安装（选极速安装）。
4. **装 Node.js**：「网站 → Node 项目」页面里点「Node 版本管理器」（或者在软件商店搜「Node.js 版本管理器」先装上），安装 **v22 的最新版**（22.13 以上）或者 v24。
5. 进面板后建议到「面板设置」改一个自己记得住的强密码。宝塔的密码等于服务器的钥匙，不要告诉别人。

## 三、部署到服务器

### 1. 上传代码

服务器上只需要 `server` 和 `admin-web/dist` 两个文件夹，放成这个样子：

```
/www/wwwroot/jinshan/
  server/             服务器程序
  admin-web/dist/     电脑网页后台
```

做法：在电脑上把 `D:\进山咖啡小程序` 里的 `server` 和 `admin-web` 两个文件夹一起压缩成 `jinshan.zip` → 宝塔「文件」→ 进入 `/www/wwwroot` → 新建文件夹 `jinshan` → 进去上传 `jinshan.zip` → 右键「解压」。

### 2. 填配置文件

在宝塔「文件」里进入 `/www/wwwroot/jinshan/server`，把 `config.example.json` 复制一份，改名为 `config.json`，双击打开编辑：

| 字段 | 填什么 |
| --- | --- |
| `appId` | 小程序 AppID，已经填好 `wx8310059ba8f45927` |
| `appSecret` | 公众平台「开发管理 → 开发设置 → AppSecret」点生成，复制过来。**只填在这里，不要发给任何人、不要放进代码或聊天里** |
| `publicUrl` | `https://你的域名`（末尾不要斜杠），微信支付的通知地址用它 |
| `ownerCode` | 自己定一串字符（比如 8 位以上的字母数字），绑定店主时要输入它，防止别人抢先绑定 |
| `port`、`host` | 保持 `3000` 和 `127.0.0.1`（只让 Nginx 访问，外面直接访问不了） |
| `pay` | 开通微信支付后再填，见「六、开通微信支付」 |

`config.json`、数据文件夹 `data/` 和证书文件夹 `cert/` 都不会上传到 GitHub，只在服务器上。

如果公众平台「开发设置」里开了「IP 白名单」，把服务器的公网 IP 加进去，否则服务器换不到登录信息。

### 3. 在宝塔里添加 Node 项目

「网站 → Node 项目 → 添加 Node 项目」：

- 项目目录：`/www/wwwroot/jinshan/server`
- 启动选项：选 `start`（就是 package.json 里的启动命令）；没有这个选项时，自定义命令填 `node app.js`
- 项目端口：`3000`
- 运行用户：`www`
- Node 版本：刚才装的 v22 或 v24
- 绑定域名：填你的域名（备案前先不填）
- 勾上开机启动

添加好后状态是「运行中」就行。点「日志」应该能看到「进山咖啡服务器已启动」。如果日志里有 `EACCES`（没有权限），在「文件」里右键 `jinshan` 文件夹 →「权限」→ 所有者改成 `www`，勾上应用到子目录，再重启项目。

### 4. 配 HTTPS

Node 项目列表里点这个项目的「设置」→「SSL」→「Let's Encrypt」→ 勾上域名申请证书 → 打开「强制 HTTPS」。证书到期前宝塔会自动续。

浏览器打开 `https://你的域名/healthz` 显示 `{"ok":true}`，`https://你的域名/admin/` 能看到网页后台的登录页，就部署好了。

### 5. 配小程序

1. **服务器域名**：公众平台「开发管理 → 开发设置 → 服务器域名」，在 `request 合法域名`、`uploadFile 合法域名`、`downloadFile 合法域名` 三处都填 `https://你的域名`。
2. **服务器地址**：用记事本打开 `miniprogram/config.js`，把 `apiBase` 改成 `'https://你的域名'`。
3. **导入项目**：微信开发者工具 → 导入 → 目录选 `D:\进山咖啡小程序`（选外层这个文件夹，不是里面的 `miniprogram`）→ AppID 已经写在 `project.config.json` 里。
4. **绑定店主**：点「编译」运行 →「我的」→「店主绑定」，填称呼和配置文件里的 `ownerCode`。第一个绑定的人就是店主，绑定后这个入口会消失。
5. **建菜单**：「我的」→「管理后台」→「商品管理」→「导入示例菜单试试」，再把示例改成店里的真实商品。也可以先在「分类管理」建分类，再新增商品。
6. **建书架**：「书目管理」→「导入示例试试」会放几本示例书和两条计费规则（按小时 ¥8、包天 ¥39 送一杯咖啡），在「计费规则」里改成店里的价格。书多的话用电脑网页后台批量导入。
7. **生成桌码**：「桌台和桌码」→ 添加桌号 → 生成桌码 → 存到相册，打印出来贴在桌上。小程序发布前想用手机扫码测试，先打开「生成体验版桌码」，并在公众平台把测试的人加为体验成员。
8. **在开发者工具里模拟扫桌码**：顶部「普通编译」下拉 →「添加编译模式」→ 启动页面选 `pages/menu/menu`，启动参数填 `t=5`（5 是桌号）。
9. 试用没问题后，开发者工具点「上传」，在公众平台提交审核、发布。

## 四、备案下来之前先测试

备案期间域名用不了，可以先用服务器 IP 加 3000 端口把小程序跑起来试：

1. `config.json` 里把 `host` 改成 `"0.0.0.0"`，重启 Node 项目。
2. 放行 3000 端口：轻量应用服务器控制台 →「防火墙」→ 添加规则，TCP 端口 `3000`；宝塔「安全」里也放行 `3000`。
3. 浏览器打开 `http://服务器IP:3000/healthz` 显示 `{"ok":true}`；`http://服务器IP:3000/admin/` 是网页后台。
4. `miniprogram/config.js` 的 `apiBase` 先填 `'http://服务器IP:3000'`。开发者工具右上角「详情 → 本地设置」勾上「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」。手机上用「预览」扫码打开后，点右上角「…」→「开发调试」，重新进入小程序才能访问。
5. 这时候是 http，没有加密，测试期间网页后台别用自己常用的密码。

备案下来、配好 HTTPS 以后：`host` 改回 `"127.0.0.1"` 并重启，删掉两处防火墙里的 3000 端口，`apiBase` 改成 `https://你的域名`。

## 五、电脑网页后台

网址是 `https://你的域名/admin/`（直接打开 `https://你的域名` 也会跳过去），员工在小程序「管理后台 → 电脑网页后台」页面能复制。想换成别的网址，填进 `miniprogram/config.js` 的 `webAdminUrl`。

**登录**：打开网址，默认显示一个小程序码。店主或员工用微信扫一扫（或在小程序「管理后台 → 扫码登录电脑」里扫），手机上点「确认登录」，电脑就以这个人的身份登录，只能看到他角色的页面。二维码 3 分钟有效、只能用一次，确认页会提醒只在自己面前的电脑上确认。

- 小程序还没发布时，正式版小程序码扫不开，网页会自动改用体验版码，扫码的人要先在公众平台加为体验成员。
- 手机不在身边时可以切到「账号密码」：每个人在小程序「管理后台 → 电脑网页后台」给自己设账号和密码（至少 8 位，字母加数字）。密码只存加密后的结果；输错 5 次锁 15 分钟。
- 不管哪种方式，登录 7 天后要重新登录；店主在「员工管理」里移除员工或停用网页账号，那个人在电脑上马上退出。

网页后台能做的：

- **每日汇总**（店主）：选日期范围看咖啡和借书的实收、未收、赠饮券发放和抵扣、吧台和微信各收了多少、卖得最多的商品，可以导出表格。充值的钱在充值当天算进实收；用余额付的单不再算一次，单独列在「余额消费」。
- **会员储值**：按会员号或备注找会员，看余额、会员到期日和每一笔流水，吧台代充、改备注；店主还能调整余额和会员日期、看储值汇总。「储值设置」（店主）配开关、免费分类和充值档位。
- **订单处理、借阅处理**：停在页面上会自动刷新，有新单响铃（浏览器第一次需要点一下页面才允许出声）。订单处理还能打小票：每单后面有「打印」，收银电脑上可以打开自动打印（见下面「收银电脑打小票」）。
- **消息通知**（店主）：选出餐通知和借书到期提醒用公众平台里的哪个模板（见「日常使用」）。
- **书目管理**：「批量导入」支持 .xlsx 和 .csv，第一行写表头 `书名、作者、ISBN、分类、册数、简介`，只有书名必填。页面上可以下载模板，导入前会先预览，ISBN 重复的会跳过。
- 商品、分类、桌码、计费规则、员工、店铺设置，和小程序后台一样。

时间按电脑的时区显示，店里电脑的时区要设成北京时间。

## 六、开通微信支付

微信支付的通知要发到 `https://你的域名`，所以要等域名备案、HTTPS 配好以后再开。

1. **申请商户号**：用个体户营业执照在微信支付商户平台申请，开通「JSAPI 支付」。
2. **关联小程序**：商户平台「产品中心 → AppID 账号管理」关联 `wx8310059ba8f45927`，再到公众平台「微信支付」里确认关联。
3. **拿到密钥**：商户平台「账户中心 → API 安全」：
   - 申请 API 证书，用官方证书工具生成，下载后里面有 `apiclient_key.pem`（商户私钥），「管理证书」里能看到证书序列号。
   - 设置 APIv3 密钥：自己定 32 位字母数字，记下来。
   - 如果页面上有「微信支付公钥」，也申请一个，下载 `pub_key.pem`，记下公钥 ID（`PUB_KEY_ID_` 开头）。配了它，服务器会额外核对通知确实来自微信。
4. **放到服务器**：宝塔「文件」在 `/www/wwwroot/jinshan/server` 里新建文件夹 `cert`，把 `apiclient_key.pem`（和 `pub_key.pem`）上传进去。然后编辑 `config.json` 的 `pay`：

   ```json
   "pay": {
     "mchId": "商户号",
     "serialNo": "API 证书序列号",
     "privateKeyFile": "cert/apiclient_key.pem",
     "apiV3Key": "32 位 APIv3 密钥",
     "publicKeyFile": "cert/pub_key.pem",
     "publicKeyId": "PUB_KEY_ID_开头的公钥 ID"
   }
   ```

   没有微信支付公钥时，`publicKeyFile` 和 `publicKeyId` 留空。改完在宝塔里重启 Node 项目，日志里会显示「微信支付已配置」。
5. **打开开关**：小程序「管理后台 → 店铺设置」（或网页后台「店铺设置」）会显示商户号，打开「微信支付」。「也能到吧台付」打开时顾客可以二选一，关掉就只能在线付。
6. 自己先下一单真付一次，到后台取消这单，看钱有没有原路退回。

付款结果以向微信查单为准：支付通知到了会先解密、查单、核对金额再标成已付，伪造的通知不起作用；通知没到时，顾客页面也会主动查单补上。店员取消已微信付款的单会自动原路退款；在吧台收的钱取消后要线下退，后台会提醒。商户私钥和 APIv3 密钥只放在服务器上，不要发给任何人。

## 七、数据、备份和更新

- **数据**都在 `/www/wwwroot/jinshan/server/data`：`jinshan.db` 是数据库，`uploads/` 是商品图、书封面和桌码，`backups/` 是每天凌晨 4 点以后自动备份的数据库，保留 14 天。
- **多一层保险**：轻量应用服务器控制台 →「快照」设置定期快照；也可以隔一阵把 `backups` 里最新的文件下载到电脑上。
- **从备份恢复**：在宝塔里停止 Node 项目 → 把 `data/jinshan.db` 改名留底，同时删掉旁边的 `jinshan.db-wal`、`jinshan.db-shm` → 把要恢复的备份复制成 `data/jinshan.db` → 启动项目。
- **更新代码**：把新的 `server` 和 `admin-web` 压缩上传，解压时覆盖。`config.json`、`data/`、`cert/` 不在压缩包里，不会被覆盖，但不要手动删掉它们。更新完在宝塔里重启 Node 项目。
- **看报错**：宝塔 Node 项目的「日志」。

## 八、收银电脑打小票

店里收银电脑自带的小票机就能打，不用另买打印机。收银电脑一直开着网页后台的「订单处理」，来新单就响铃并自动打一张：取餐号、桌号或外带、预约时间、商品和规格、备注、金额、付没付款。下面按 Windows 写：

1. **小票机设成默认打印机**：先确认小票机能打测试页。Windows「设置 → 蓝牙和其他设备 → 打印机和扫描仪」，关掉「让 Windows 管理默认打印机」，点小票机 →「设为默认值」。
2. **纸张**：在小票机的「打印首选项」里把纸张选成和纸卷一样宽的（58mm 或 80mm，驱动里的叫法各家不同），页边距尽量设成 0。
3. **做一个不弹打印框的快捷方式**：桌面右键 →「新建 → 快捷方式」，位置填（Windows 自带的 Edge 浏览器）：

   ```
   "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --kiosk-printing http://服务器IP:3000/admin/#/orders
   ```

   用 Chrome 的话把前半段换成 `"C:\Program Files\Google\Chrome\Application\chrome.exe"`。备案后换成 `https://你的域名/admin/#/orders`。**双击前先把这个浏览器的窗口全部关掉**，不然 `--kiosk-printing` 不生效，还是会弹打印框。Edge 关掉窗口后有时还在后台运行：在 Edge「设置 → 系统和性能」里关掉「启动增强」和「关闭 Microsoft Edge 后继续运行后台扩展和应用」。
4. 用快捷方式打开，登录，进「订单处理」→ 右上角「小票打印」：打开「自动打印新单」，选纸宽，需要的话选每单打 2 张（一张给顾客），点「打一张试试」。这些设置只存在这台电脑上，别的电脑开着订单页不会重复打。
5. 平时让这个页面一直开着，不要最小化（浏览器会放慢后台页面的刷新），开着「自动刷新」，开机后先点一下页面，响铃才有声音。

只打开页面以后来的新单；页面关着时来的单，打开后在订单后面点「打印」补打。打出来字被截掉的话，换一下纸宽，或者检查打印首选项里的纸张。

## 九、洗车小程序（黑镜车体护理车房）

洗车小程序和咖啡共用这台服务器、同一个数据库、同一个网页后台，代码在 `miniprogram-carwash/`。它是另一个小程序（另一个 AppID），洗车店是另一张执照，所以微信支付也用洗车自己的商户号，钱进洗车店的账户。

- **顾客**：首页看项目和价格 → 选到店或上门 → 选时间段（满了的约不了）→ 上门的在地图上选车停的位置，按直线距离算上门费，超出范围按店里的设置拒接或加价 → 用次卡抵、洗车余额、微信支付或到店付。订单里能看进度、付款、取消（按店里的取消规则）、确认洗好了。
- **技师**：洗车小程序「我的 → 员工：接单和收银」：接单 → 出发（上门的）→ 开始洗 → 洗好了，顾客确认或者过了设置的时间自动确认；到店付的收了钱点「收到钱了」；到店收银给会员充值、办卡、扣次卡。技师只看得到待接的单和派给自己的单的地址、电话。
- **洗车会员**：会员号和咖啡通用，**余额分开**（洗车充的钱只能洗车用）；充值档位、次卡（几次、多少钱、几天有效、能洗哪些项目）、会员价都在后台配。储值和次卡不在线退，店长线下退钱后在后台扣余额或退卡，写原因，有流水。
- **送咖啡券**：在后台配「充值满多少 / 办哪种次卡，送几张多少钱的咖啡券」。券在两个小程序「我的券」里都看得到，只能在进山咖啡用，点单时自动抵扣；退卡时可以一起撤回。
- **美团、抖音团购核销**：接口位置留好了（`server/functions/redeem.js`），选好聚合核销服务商、拿到接口 Key 后再接。

### 1. 注册洗车小程序

用洗车店的个体户执照在 [微信公众平台](https://mp.weixin.qq.com) 注册小程序，拿到 AppID 和 AppSecret。AppSecret 只填在服务器的 `config.json` 里，不要发给别人、不要写进代码。

### 2. 开放平台绑定两个小程序（让两边认同一个人）

在 [微信开放平台](https://open.weixin.qq.com) 注册账号、完成开发者资质认证，在「管理中心 → 小程序」里把进山咖啡和洗车两个小程序都绑上（不同执照的小程序可以绑在同一个开放平台账号下）。绑好以后同一个微信号在两个小程序里是同一个人：会员号相同、送的券两边都看得到、店主和员工身份两边通用。没绑之前两个小程序各算各的人，也不影响各自使用。

**绑定之前已经在咖啡小程序里有余额、订单的人（包括店主自己）**：绑定后先打开一次咖啡小程序，再打开洗车小程序，原来的数据就接上了。

### 3. 服务器配置

编辑 `/www/wwwroot/jinshan/server/config.json`，加上 `carwash` 一段：

```json
"carwash": {
  "appId": "洗车小程序的 AppID",
  "appSecret": "洗车小程序的 AppSecret",
  "pay": {
    "mchId": "",
    "serialNo": "",
    "privateKeyFile": "cert/carwash/apiclient_key.pem",
    "apiV3Key": "",
    "publicKeyFile": "",
    "publicKeyId": ""
  }
}
```

洗车的商户号下来以前 `pay` 里留空，顾客可以先用到店付款和洗车余额（店里代充）。申请商户号的步骤和「六、开通微信支付」一样，只是用洗车店的执照、关联洗车小程序的 AppID，证书放到 `server/cert/carwash/`。支付通知地址自动是 `https://你的域名/pay/notify/carwash`，服务器只认洗车商户号的密钥。改完重启 Node 项目，日志里会显示洗车小程序和洗车微信支付有没有配好。

### 4. 小程序代码和后台

1. 微信开发者工具「导入项目」选 `miniprogram-carwash` 文件夹（不是仓库根目录），把 `miniprogram-carwash/project.config.json` 里的 `appid` 从 `touristappid` 换成洗车的 AppID。
2. `miniprogram-carwash/config.js` 的 `apiBase` 填和咖啡小程序一样的服务器地址。
3. 洗车小程序的公众平台「开发管理 → 服务器域名」也要加上服务器域名（备案、HTTPS 以后）。
4. 用户隐私保护指引里声明「选择的位置信息」（顾客在地图上选上门地址）和「剪切板」（员工复制网页后台网址），以公众平台的提示为准。

### 5. 后台设置（网页后台左上角切到「洗车」）

- **洗车店设置**：店名、地址、电话、店的位置（腾讯地图坐标），营业时间、每段多长、到店和上门每段各接几单、能约几天内、至少提前多久，上门半径、上门费、超出半径怎么办，免费取消时限、之后取消怎么处理（不能取消 / 扣钱 / 照样退）、多久自动确认完成，付款方式。**这些都没有默认值**，没填齐之前顾客约不了，页面顶上会列出还差哪几项。
- **服务项目**：名称、价格、会员价、大约多久、能到店还是能上门。
- **储值和次卡**：打开洗车储值、写储值说明和退费须知，加充值档位和次卡。
- **送咖啡券**：充值、办卡送咖啡券的规则。
- **技师管理**：生成邀请码，技师在洗车小程序「我的」底部点「我是员工，用邀请码绑定」。店主可以邀请洗车店长（只管洗车，看不到咖啡）。
- **预约订单**：日历看每天约了多少、还有几单没人接，能派单、改派、推进、登记收款、取消（全额退）。
- **到店收银**：按会员号给顾客充值、办卡、扣次卡；技师也能用。

还没做：预约成功、技师出发的微信提醒（订阅消息），等洗车小程序注册好、选好模板再加。

## 日常使用

- **接单**：管理后台 →「订单处理」。停在这个页面时每 8 秒自动刷新，有新订单会响铃和震动，屏幕也不会自动熄灭。手机锁屏或切到别的应用就收不到提醒，所以店里用收银电脑开着网页后台的订单页，响铃并自动打小票（见「八、收银电脑打小票」）。
- **收款**：吧台收到钱后点「已收款」；微信付的会自动变成「微信已付」。
- **改价和售罄**：「商品管理」里直接点开改价格；开关控制上架；「标售罄」后顾客能看到但点不了。
- **借书**：顾客在「书架」选书和计费方式下单，拿到借书号。店员在「借阅处理」里收款（微信付的自动变已收），把书交给顾客时点「交书，开始计时」。按小时的从交书开始计时，超过时间（扣掉宽限分钟）按小时补超时费，不满 1 小时按 1 小时算；包天的当天打烊前还。还书时点「还书」，有超时费会提示金额。
- **赠饮券**：包天规则里可以设送几杯、限哪些饮品、每杯最多抵多少钱。借书付款后自动发券，只在当天有效，顾客点单时自动抵扣；借阅被取消时没用的券作废。
- **首页轮播**：店主在「首页轮播」里加，点开可以去某个商品、某本书、领券中心，或者只放一张图。图片建议 750×400，不传就用商品图或书封面。商品或书下架后那张轮播自动不显示。一张都没配时，自动放最近上架的商品和书。
- **代金券**：店主在「代金券」里建，比如满 30 减 5，设有效天数（领取当天算第 1 天）、一共发几张、每人限领几张。顾客在首页「领券中心」自己领，下单时自动挑抵得最多的一张，也可以换或不用；一单最多一张，可以和赠饮券一起用，门槛按用完赠饮券后的金额算。订单取消时券退回给顾客。停发或删除后顾客领不到了，已经领的照样能用。
- **营业时间和预约**：在「店铺设置」里改营业时间，显示在顾客首页。预约要先付款（微信支付或会员余额），所以开通微信支付或打开会员储值以后首页的「预约」才能用。顾客能约今天和明天营业时间里的时间，每 15 分钟一档，最早 30 分钟后；下单后 15 分钟内要付款，没付的自动取消、券退回。没付款的预约单店员看不到；付了以后出现在订单处理里，标着「预约 15:30」，排在约定时间前 10 分钟的位置。约明天的单算在明天，取餐号也用明天的。
- **会员储值设置**：店主在「储值设置」里打开开关，加充值档位：充多少、送多少、送几天会员（一年填 365），不填名字自动叫「充 300 送 100」；可以排序、下架。勾选会员免费看的书的分类（默认漫画，分类来自录书时填的分类）。改档位只影响以后的充值。
- **会员号和吧台代充**：顾客第一次打开「我的 → 会员中心」就有一个 5 位会员号（从 10001 开始）。没开微信支付时，顾客到吧台付钱、报会员号，店员在「会员储值」里搜会员号，点「充值」选档位；开了微信支付顾客也能在会员中心自己充。会员天数从充值当天算第 1 天，已经是会员的从原来的到期日往后加。可以给会员写备注（比如姓氏、手机尾号），之后按备注也能搜到。
- **余额付款**：开了储值以后，顾客确认订单、借书、付超时费时可以选「余额」，下单就扣、店员看到的是「余额已付」，不用再收钱。用余额付的单取消时钱退回余额。余额不够时提示去充值。
- **会员免费看**：会员期内借免费分类的书，在书详情选「会员畅读」，不收钱、不计时，当天打烊前还，不送赠饮券。
- **退款和调整**：储值不退。特殊情况店主线下把钱退给顾客，再在会员详情里点「调整」扣掉对应余额（也能加钱、改会员到期日或取消会员），必须写原因。只有店主能调整，咖啡师只能代充和改备注。每一笔充值、消费、退回、调整都记在流水里，写着是谁操作的。
- **出餐通知和借书到期提醒**：用的是微信的订阅消息，不花钱，不用等微信支付和备案。先在公众平台「订阅消息」里从模板库选模板（取餐用「取餐提醒」一类，借书用「到期提醒」一类），再到网页后台「消息通知」里选上，页面会显示每个字段会填什么。顾客下单时会弹出「允许」，点了允许，店员点「制作完成」后顾客微信里收到通知；按小时借书的，到期前 10 分钟收到还书提醒。微信规定点一次允许只能收一条，所以每次下单都会问。小程序没发布前测试时，把「点通知打开」选成开发版或体验版，发布后改回正式版。
- **加员工**：「员工管理」→「邀请员工」→ 选角色，把 6 位邀请码告诉员工。员工打开小程序，在「我的」页面底部点「我是店员，用邀请码绑定」。

## 数据集合

| 集合 | 存什么 |
| --- | --- |
| staff | 员工：店主、咖啡师、书籍管理员（文档 ID 是员工的 openid），以及网页后台账号和加密后的密码 |
| staff_invites | 员工邀请码，24 小时有效，只能用一次 |
| mp_sessions | 小程序的登录状态（只存摘要），30 天过期，过期后小程序自动重新登录 |
| web_sessions | 网页后台的登录状态（只存 token 的摘要），7 天过期 |
| web_login_tickets | 网页后台扫码登录的二维码：3 分钟有效、只能用一次，一小时后自动清掉 |
| settings | 店铺设置：营业时间、微信支付开关、是否允许吧台付（商户号和密钥在服务器配置文件里）；ID 为 member 的一条是储值设置：开关、会员免费看的分类、储值说明；ID 为 notify 的一条是消息通知用的模板和字段对应；ID 为 carwash 的一条是洗车店设置，carwash_member 是洗车储值设置 |
| banners | 首页轮播：点开去哪（商品、书、领券中心、只放图）、图片、文字、顺序、是否显示 |
| counters | 每天的取餐号、借书号计数 |
| coffee_categories | 菜单分类和顺序 |
| coffee_products | 商品：价格（分）、规格和加价、上架、售罄 |
| coffee_orders | 订单：桌号或外带、明细、金额、赠饮券和代金券抵扣、取餐号、付款方式和状态、制作状态；预约单还有取餐时间和是否在等付款；notifyReady 表示顾客允许了出餐通知 |
| coffee_coupons | 代金券设置：减多少、满多少可用、有效天数、一共发几张、每人限领、已领多少、是否发放 |
| coffee_tables | 桌号和桌码图片 |
| book_books | 书目：书名、作者、ISBN、分类、册数和在架数量 |
| book_rules | 计费规则：按小时（单价、最少最多几小时、宽限分钟）或包天（价格、送几杯、限哪些饮品、每杯最多抵多少） |
| book_rentals | 借阅：借的书、下单时的计费快照、租金、借书号、交书和到期时间、超时费；notifyDue 表示要到期提醒，dueReminded 表示已经提醒过 |
| members | 会员：会员号、余额、会员到期日、累计充值和赠送、累计消费、备注（文档 ID 是顾客的 openid） |
| member_logs | 余额流水：充值、消费、退回、调整，每笔记着变动金额、变动后的余额、关联的订单或借阅、操作人和原因 |
| member_plans | 充值档位：充多少、送多少、送几天会员、顺序、是否上架 |
| member_recharges | 在线充值单：档位快照、金额、微信支付状态 |
| wx_users | 两个小程序认人：unionid → 用户 id（第一次见到时那个小程序的 openid）和在两个小程序里各自的 openid |
| cw_services | 洗车项目：价格、会员价、大约多久、能到店还是上门、顺序、是否上架 |
| cw_orders | 洗车预约：项目、到店或上门、时段、地址快照、车牌车型、价格明细（会员价、上门费、次卡抵扣）、付款方式和状态、技师、状态（待接单 → 已接单 → 已出发 → 服务中 → 待确认 → 已完成 / 已取消）、取消和退款 |
| cw_addresses | 顾客的上门地址：联系人、电话、地图上的位置、详细位置、是否默认 |
| cw_members / cw_member_logs | 洗车余额和流水（和咖啡的分开，会员号借咖啡的） |
| cw_plans / cw_recharges | 洗车充值档位、在线充值单 |
| cw_card_types / cw_cards / cw_card_logs / cw_card_orders | 次卡种类、顾客手里的卡（剩几次、到期日）、每一次办卡用卡退回调整退卡、在线办卡单 |
| cw_link_rules | 洗车送咖啡券的规则 |
| vouchers | 顾客手里的券。赠饮券：哪次借书送的、当天有效；代金券（type 是 cash）：领的哪种券、领取时的金额和门槛、到期日；洗车送的代金券记着 issuedBy: carwash、能在哪家用（usableShops）。都记着用在哪个订单 |

每个集合是 SQLite 里的一张表，常用的查询字段自动建了索引。金额都用“分”存整数，订单和借书的金额只在服务器上按数据库里的价格计算。借阅记录保存下单时的计费规则快照，之后改规则不影响已经下的单。

## 开发

- `npm test`：在内存数据库里把点单、借书计时、赠饮券、会员储值和余额付款、出餐通知和到期提醒、网页登录、在线支付和退款，洗车预约（防超约、上门费、取消规则、技师接单）、洗车储值和次卡（防重复扣）、送咖啡券、两个小程序认同一个人等流程跑一遍，也测数据库、微信接口（含订阅消息）、微信支付 v3 签名和解密、整个 HTTP 服务器。需要 Node 22.13 以上，不用安装依赖。
- 本地跑服务器：`cd server`，复制 `config.example.json` 为 `config.json`，`npm start`，打开 http://127.0.0.1:3000/admin/ 。
- 网页后台：`cd admin-web && npm install`，`npm run build` 打包到 `dist`；`npm run mock` 用假数据预览（打开 http://localhost:8787 ，账号 boss，密码 jinshan2026，扫码登录页下面有「预览模式：模拟手机确认」）；`npm run dev` 开发时配合 `npm run mock` 一起用。
