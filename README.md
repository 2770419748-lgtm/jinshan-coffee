# 进山咖啡小程序

进山咖啡的微信小程序：顾客扫桌码点单，店主和员工在小程序里管理菜单、订单和桌码。书本租赁、电脑网页后台、微信支付在后面几步加入。

后端用微信云开发，不需要自己买服务器。

## 进度

- [x] 第 1 步：咖啡点单，小程序里的咖啡后台
- [ ] 第 2 步：书本租赁（按小时、包天送咖啡的计费规则）
- [ ] 第 3 步：电脑网页后台
- [ ] 第 4 步：微信支付和上线

## 第一次运行

需要先准备：小程序 AppID（用个体户在 [微信公众平台](https://mp.weixin.qq.com) 注册），以及微信开发者工具。

1. **导入项目**：打开微信开发者工具 → 导入 → 目录选这个文件夹（比如 `D:\进山咖啡小程序`）→ AppID 填自己的。测试号不能用云开发，一定要用正式的 AppID。
2. **开通云开发**：点工具栏的「云开发」→ 开通 → 新建环境。环境建好后，把环境 ID 填进 `miniprogram/config.js` 的 `envId`。
3. **部署云函数**：在左侧文件树里，右键 `cloudfunctions/common` →「上传并部署：云端安装依赖」；`cloudfunctions/coffee` 也一样操作一次。如果文件夹没显示云朵图标，先右键 `cloudfunctions` →「选择云开发环境」。
4. **设置数据库权限**：第一次打开小程序时会自动建好数据库集合。建议到「云开发控制台 → 数据库」，把每个集合的权限改成「仅管理端可读写」。小程序所有读写都经过云函数，这样最安全。
5. **设置存储权限**：「云开发控制台 → 存储 → 权限设置」选「所有用户可读，仅创建者可读写」，顾客才能看到商品图片。
6. **绑定店主**：点「编译」运行 →「我的」→「店主绑定」，填称呼。第一个绑定的人就是店主，绑定后这个入口会消失。
   - 更稳妥的做法：绑定前到「云开发控制台 → 云函数 → common → 函数配置 → 环境变量」加一个 `OWNER_CODE`（自己定一串字符），绑定店主时就必须输入它。
7. **建菜单**：「我的」→「管理后台」→「商品管理」→「导入示例菜单试试」，再把示例改成店里的真实商品。也可以先在「分类管理」建分类，再新增商品。
8. **生成桌码**：「桌台和桌码」→ 添加桌号 → 生成桌码 → 存到相册，打印出来贴在桌上。小程序发布前想用手机扫码测试，先打开「生成体验版桌码」，并在公众平台把测试的人加为体验成员。
9. **在开发者工具里模拟扫桌码**：顶部「普通编译」下拉 →「添加编译模式」→ 启动页面选 `pages/menu/menu`，启动参数填 `t=5`（5 是桌号）。

## 日常使用

- **接单**：管理后台 →「订单处理」。停在这个页面时每 8 秒自动刷新，有新订单会响铃和震动，屏幕也不会自动熄灭。手机锁屏或切到别的应用就收不到提醒，第 4 步会加微信消息通知。
- **收款**：现在顾客都是到吧台付款，店员收到钱后点「已收款」。微信支付开通后会改成在线付。
- **改价和售罄**：「商品管理」里直接点开改价格；开关控制上架；「标售罄」后顾客能看到但点不了。
- **加员工**：「员工管理」→「邀请员工」→ 选角色，把 6 位邀请码告诉员工。员工打开小程序，在「我的」页面底部点「我是店员，用邀请码绑定」。咖啡师只能进咖啡后台，书籍管理员只能进书籍后台。

## 上线前还要做

- 小程序备案和微信认证（在公众平台提交）
- 用户隐私保护指引：在公众平台「设置 → 服务内容声明 → 用户隐私保护指引」里声明用到的「选中的照片或视频信息」（上传商品图）和「相册（仅写入）权限」（保存桌码）
- 服务类目选餐饮相关类目，需要的资质以公众平台的要求为准
- 订单多了以后，在「云开发控制台 → 数据库 → coffee_orders → 索引管理」加两个索引：`day + status + seq`，`_openid + createdAt`

## 目录

```
miniprogram/            小程序
  pages/                顾客端：首页、点单、确认订单、订单详情、我的订单、我的、绑定
  admin/                管理后台（分包）：首页、订单处理、商品、分类、桌码、员工
  utils/                调云函数、购物车、桌号、权限检查、WXML 格式化
cloudfunctions/
  common/               登录、店主绑定、员工邀请和权限
  coffee/               菜单、下单、订单处理、商品分类桌台
tests/                  本地测试（不参与小程序打包）
```

## 数据集合

| 集合 | 存什么 |
| --- | --- |
| staff | 员工：店主、咖啡师、书籍管理员（文档 ID 是员工的 openid） |
| staff_invites | 员工邀请码，24 小时有效，只能用一次 |
| counters | 每天的取餐号计数 |
| coffee_categories | 菜单分类和顺序 |
| coffee_products | 商品：价格（分）、规格和加价、上架、售罄 |
| coffee_orders | 订单：桌号或外带、明细、金额、取餐号、付款状态、制作状态 |
| coffee_tables | 桌号和桌码图片 |

咖啡模块只读写 `coffee_` 开头的集合，第 2 步的书籍模块会用 `book_` 开头的集合，两边分开管理。金额都用“分”存整数，下单金额只在云端按数据库里的价格计算。

- `npm test`：用内存数据库模拟云开发，把店主绑定、导入菜单、下单、接单出餐等流程跑一遍。需要 Node 18 以上，不用安装依赖。
- `cloudfunctions/common/lib/base.js` 和 `cloudfunctions/coffee/lib/base.js` 是同一份文件，改了要两边同步，测试会检查。
