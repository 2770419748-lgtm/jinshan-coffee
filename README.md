# 进山咖啡小程序

进山咖啡的微信小程序和管理后台：

- **顾客**：扫桌码点咖啡，也能不扫码点外带；在书架上选书、选计费方式下单，付款后到吧台取书；包天借书送的咖啡变成赠饮券，点单时自动抵扣。
- **店里**：小程序里有管理后台（接单、借书处理、改菜单、录书、计费规则、员工），按微信身份识别店主和员工，不用账号密码；电脑上还有网页后台，用微信扫码登录，多了每日汇总和 Excel 批量导入书目。
- **付款**：没开通微信支付时顾客到吧台付，店员点「已收款」；开通后在「店铺设置」填商户号打开开关，顾客就能在小程序里直接付，取消已付款的单会原路退款。

后端用微信云开发，不需要自己买服务器。咖啡和书籍分开管理：咖啡模块只读写 `coffee_` 开头的集合，书籍模块只读写 `book_` 开头的集合，员工角色也分开（咖啡师只进咖啡后台，书籍管理员只进书籍后台）。

## 一、第一次运行小程序

需要先准备：小程序 AppID（用个体户在 [微信公众平台](https://mp.weixin.qq.com) 注册），以及微信开发者工具。

1. **导入项目**：打开微信开发者工具 → 导入 → 目录选这个文件夹（比如 `D:\进山咖啡小程序`）→ AppID 填自己的。测试号不能用云开发，一定要用正式的 AppID。
2. **开通云开发**：点工具栏的「云开发」→ 开通 → 新建环境。环境建好后，把环境 ID 填进 `miniprogram/config.js` 的 `envId`。
3. **部署云函数**：在左侧文件树里，右键 `cloudfunctions/common` →「上传并部署：云端安装依赖」；`cloudfunctions/coffee`、`cloudfunctions/book` 也各操作一次，一共三个。`common` 和 `coffee` 要生成小程序码（扫码登录、桌码），`config.json` 里已经申请了 `wxacode.getUnlimited` 权限，部署时会一起生效。如果文件夹没显示云朵图标，先右键 `cloudfunctions` →「选择云开发环境」。以后改了云函数代码，也要重新上传对应的那个。
4. **设置数据库权限**：第一次打开小程序时会自动建好所有数据库集合。建议到「云开发控制台 → 数据库」，把每个集合的权限改成「仅管理端可读写」。小程序和网页后台的所有读写都经过云函数，这样最安全。
5. **设置存储权限**：「云开发控制台 → 存储 → 权限设置」选「所有用户可读，仅创建者可读写」，顾客才能看到商品图片和书的封面。
6. **绑定店主**：点「编译」运行 →「我的」→「店主绑定」，填称呼。第一个绑定的人就是店主，绑定后这个入口会消失。
   - 更稳妥的做法：绑定前到「云开发控制台 → 云函数 → common → 函数配置 → 环境变量」加一个 `OWNER_CODE`（自己定一串字符），绑定店主时就必须输入它。
7. **建菜单**：「我的」→「管理后台」→「商品管理」→「导入示例菜单试试」，再把示例改成店里的真实商品。也可以先在「分类管理」建分类，再新增商品。
8. **建书架**：「书目管理」→「导入示例试试」会放几本示例书和两条计费规则（按小时 ¥8、包天 ¥39 送一杯咖啡），在「计费规则」里改成店里的价格。书多的话用电脑网页后台批量导入。
9. **生成桌码**：「桌台和桌码」→ 添加桌号 → 生成桌码 → 存到相册，打印出来贴在桌上。小程序发布前想用手机扫码测试，先打开「生成体验版桌码」，并在公众平台把测试的人加为体验成员。
10. **在开发者工具里模拟扫桌码**：顶部「普通编译」下拉 →「添加编译模式」→ 启动页面选 `pages/menu/menu`，启动参数填 `t=5`（5 是桌号）。

## 二、电脑网页后台

网页后台的文件在 `admin-web/dist`（已经打包好，直接上传就行），用的是同一个云开发环境。

1. **开启匿名登录**：「云开发控制台 → 身份认证（或「登录授权」）」里打开「匿名登录」。网页先匿名登录云开发，再靠员工扫码确认（或账号密码）换取身份，不是员工什么也做不了。
2. **填环境 ID**：用记事本打开 `admin-web/dist/config.js`，把 `envId` 改成和 `miniprogram/config.js` 一样的环境 ID。
3. **上传网站**：「云开发控制台 → 静态网站托管」开通后，把 `admin-web/dist` 里的所有文件上传到根目录。上传完会给一个默认域名，这就是网页后台的网址。
4. **加安全域名**：「云开发控制台 → 身份认证 → 安全配置（Web 安全域名）」里加上这个网址的域名，否则网页调不了云函数。
5. **把网址告诉员工**：填进 `miniprogram/config.js` 的 `webAdminUrl`，员工在小程序「电脑网页后台」页面能复制。
6. **登录**：打开网址，默认显示一个小程序码。店主或员工用微信扫一扫（或在小程序「管理后台 → 扫码登录电脑」里扫），手机上点「确认登录」，电脑就以这个人的身份登录，只能看到他角色的页面。二维码 3 分钟有效、只能用一次，确认页会提醒只在自己面前的电脑上确认。
   - 小程序还没发布时，正式版小程序码扫不开，网页会自动改用体验版码，扫码的人要先在公众平台加为体验成员。
   - 手机不在身边时可以切到「账号密码」：每个人在小程序「管理后台 → 电脑网页后台」给自己设账号和密码（至少 8 位，字母加数字）。密码只存加密后的结果；输错 5 次锁 15 分钟。
   - 不管哪种方式，登录 7 天后要重新登录；店主在「员工管理」里移除员工或停用网页账号，那个人在电脑上马上退出。

控制台的菜单名称经常调整，以实际页面为准。静态网站托管和网页端访问是否需要升级环境套餐，也以控制台提示为准。

网页后台能做的：

- **每日汇总**（店主）：选日期范围看咖啡和借书的实收、未收、赠饮券发放和抵扣、吧台和微信各收了多少、卖得最多的商品，可以导出表格。
- **订单处理、借阅处理**：停在页面上会自动刷新，有新单响铃（浏览器第一次需要点一下页面才允许出声）。
- **书目管理**：「批量导入」支持 .xlsx 和 .csv，第一行写表头 `书名、作者、ISBN、分类、册数、简介`，只有书名必填。页面上可以下载模板，导入前会先预览，ISBN 重复的会跳过。
- 商品、分类、桌码、计费规则、员工、店铺设置，和小程序后台一样。

时间按电脑的时区显示，店里电脑的时区要设成北京时间。

## 三、开通微信支付

1. 用个体户营业执照申请微信支付商户号，在商户平台把小程序的 AppID 关联上（「产品中心 → AppID 账号管理」之类的位置）。
2. 在「云开发控制台 → 设置」里找到微信支付配置，添加商户号；商户号的管理员会在微信里收到授权确认，点同意。
3. 小程序「管理后台 → 店铺设置」（或网页后台「店铺设置」）填商户号，打开「微信支付」。「也能到吧台付」打开时顾客可以二选一，关掉就只能在线付。
4. 自己先下一单真付一次，到后台取消这单，看钱有没有原路退回。

付款结果以向微信查单为准：支付回调到了会先查单、核对金额再标成已付，伪造的回调不起作用；回调没到时，顾客页面也会主动查单补上。店员取消已微信付款的单会自动原路退款；在吧台收的钱取消后要线下退，后台会提醒。

## 日常使用

- **接单**：管理后台 →「订单处理」。停在这个页面时每 8 秒自动刷新，有新订单会响铃和震动，屏幕也不会自动熄灭。手机锁屏或切到别的应用就收不到提醒，店里可以用一台常开的手机或电脑开着这个页面。
- **收款**：吧台收到钱后点「已收款」；微信付的会自动变成「微信已付」。
- **改价和售罄**：「商品管理」里直接点开改价格；开关控制上架；「标售罄」后顾客能看到但点不了。
- **借书**：顾客在「书架」选书和计费方式下单，拿到借书号。店员在「借阅处理」里收款（微信付的自动变已收），把书交给顾客时点「交书，开始计时」。按小时的从交书开始计时，超过时间（扣掉宽限分钟）按小时补超时费，不满 1 小时按 1 小时算；包天的当天打烊前还。还书时点「还书」，有超时费会提示金额。
- **赠饮券**：包天规则里可以设送几杯、限哪些饮品、每杯最多抵多少钱。借书付款后自动发券，只在当天有效，顾客点单时自动抵扣；借阅被取消时没用的券作废。
- **加员工**：「员工管理」→「邀请员工」→ 选角色，把 6 位邀请码告诉员工。员工打开小程序，在「我的」页面底部点「我是店员，用邀请码绑定」。

## 数据集合

| 集合 | 存什么 |
| --- | --- |
| staff | 员工：店主、咖啡师、书籍管理员（文档 ID 是员工的 openid），以及网页后台账号和加密后的密码 |
| staff_invites | 员工邀请码，24 小时有效，只能用一次 |
| web_sessions | 网页后台的登录状态（只存 token 的摘要），7 天过期 |
| web_login_tickets | 网页后台扫码登录的二维码：3 分钟有效、只能用一次，一小时后自动清掉 |
| settings | 店铺设置：微信支付开关、商户号、是否允许吧台付 |
| counters | 每天的取餐号、借书号计数 |
| coffee_categories | 菜单分类和顺序 |
| coffee_products | 商品：价格（分）、规格和加价、上架、售罄 |
| coffee_orders | 订单：桌号或外带、明细、金额、赠饮抵扣、取餐号、付款方式和状态、制作状态 |
| coffee_tables | 桌号和桌码图片 |
| book_books | 书目：书名、作者、ISBN、分类、册数和在架数量 |
| book_rules | 计费规则：按小时（单价、最少最多几小时、宽限分钟）或包天（价格、送几杯、限哪些饮品、每杯最多抵多少） |
| book_rentals | 借阅：借的书、下单时的计费快照、租金、借书号、交书和到期时间、超时费 |
| vouchers | 赠饮券：哪次借书送的、当天有效、用在哪个订单 |

金额都用“分”存整数，订单和借书的金额只在云端按数据库里的价格计算。借阅记录保存下单时的计费规则快照，之后改规则不影响已经下的单。

## 开发

- `npm test`：用内存数据库模拟云开发（包括微信支付），把点单、借书计时、赠饮券、网页登录、在线支付和退款等流程跑一遍。需要 Node 18 以上，不用安装依赖。
- `cloudfunctions/*/lib/base.js` 三个云函数里是同一份文件，`coffee/lib/pay.js` 和 `book/lib/pay.js` 也是同一份，改了要几处同步，测试会检查。
- 网页后台：`cd admin-web && npm install`，`npm run dev` 开发，`npm run build` 打包到 `dist`，`npm run mock` 用假数据预览。`npm run build:demo` 打包一个不用服务器的预览版到 `dist-demo`：云函数和假数据直接跑在浏览器里，可以放到任何静态网页上给别人看。
